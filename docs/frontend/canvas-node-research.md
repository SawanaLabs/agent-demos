## 节点职责表

内容类型和节点职责应分开考虑。内容类型包括文本、图片、视频、音频、蒙版；节点职责描述用户在工作流中要完成的事情。

| 职责 | 用户要做的事 | 典型节点 |
| --- | --- | --- |
| 素材输入 | 把已有内容放进流程 | 文本、图片、视频、音频 |
| AI 生成 | 根据输入创造或修改内容 | 生成图片、生成文本、生成视频 |
| 内容处理 | 对已有结果做一个明确操作 | 裁切、去背景、放大、抽帧、拼接 |
| 组织与选择 | 批量生成、比较、选择继续用哪个 | 批量、候选选择、文本拼接 |
| 查看与交付 | 检查结果、下载或导出 | 预览、结果对比、导出 |

这张表是本项目讨论中认可的分析框架，各竞品采用的菜单分类并不相同，也无需将表中所有能力一次实现。

例如，“图片”是一种内容；“生成图片”“裁切图片”“查看图片”承担不同职责。单独使用“图片”作为动作入口名称，容易让用户混淆上传素材与调用生成。

## 产品设计建议

以下为研究后的建议，仍需通过用户操作验证。

### 按用户需要控制的步骤决定节点粒度

判断一个操作是否值得成为独立节点，可以问：

- 用户会不会单独重跑这一步？
- 这一步的结果会不会被多个下游复用？
- 用户是否需要停下来检查、挑选或修改结果？
- 这一步是否有独立参数、耗时或费用？

例如，“先生成四张图，再选一张做视频”中，选择图片是重要步骤。直接自动执行所有下游，可能导致四张图都生成视频，偏离用户对结果与费用的预期。

比例、质量、模型选择可以先留在生成节点内部。需要一次比较多个模型时，再通过分支或批量能力表达。

### 连线同时表达内容与用途

同一张图片可以用作参考图片、首帧、尾帧、人物参考或风格参考。仅显示“连上了”不足以解释它将怎样影响生成。

- FLORA 文档区分视频输入中的首尾帧用途。[连线说明](https://docs.flora.ai/editor/canvas)
- Runway 要求连接兼容的内容类型，并区分文本、图片、音频、视频端口。[节点与连线说明](https://help.runwayml.com/hc/en-us/articles/45763528999699-Introduction-to-Workflows)
- 本项目图片阶段可先明确提示词输入与参考图片输入；视频阶段再增加首帧、尾帧等角色。

### 区分跟随更新的预览与固定保留的素材

建议区分三种行为：

- 预览节点跟随上游更新，用来检查当前结果。
- 保存为素材的结果固定保留，用来选定一张图后继续创作。
- 生成历史允许用户选择哪个版本供下游使用。

需要明确的产品问题：一张人物图已经用于五个镜头，再次生成新人物图后，下游是否立即改用新图？这会影响整个工作流的可控性，不能只通过视觉布局解决。

Runway 提供锁定节点输出的操作；FLORA 的更新说明包含固定文本，以及组运行不重复生成已有结果节点的行为。这些是保留满意结果的实际产品例子。[Runway 锁定节点](https://help.runwayml.com/hc/en-us/articles/45763528999699-Introduction-to-Workflows) · [FLORA 更新](https://flora.ai/updates/more-ways-to-create-2026-09-04)

### 当前 Demo 的候选入口

建议先围绕五个入口打磨：文本素材、图片素材、生成文本、生成图片、预览输出。

- “参考图”可以作为图片素材接入生成节点后的用途。
- 文生图与图生图先由同一个生成图片节点根据输入支持，界面清楚显示收到的提示词和参考图片。
- 图片生成结果可以继续接入下游；手动预览输出用于集中查看。固定素材、实时预览和历史版本的关系仍需单独确认。
- 先完成手动工作流，再让 Agent 使用同一套能力编排。

### 通过真实任务决定后续节点

优先观察三个任务：

1. 手写提示词生成图片。
2. 文本加参考图片生成新图。
3. 生成多个候选，选定一个结果，再继续修改。

记录用户在哪一步反复复制粘贴、下载再上传、担心覆盖旧结果，或者不知道该连哪里。用这些具体障碍判断下一种节点的价值，避免先扩展大量低频节点。

查了一轮 LibTV、ComfyUI、Runway、Weavy / Figma Weave、FLORA 和 Krea 的公开资料。**我的判断是：我们现在“素材 + 生成动作 + 输出”的方向成立，但要把“节点类型”和“内容类型”分开考虑。**

从这些产品里，我会提炼出下面几个原则。**这些是我的产品建议，并非所有竞品都采用同一套设计。**

**首先，内容类型和节点职责是两个维度。**

内容类型是文本、图片、视频、音频、蒙版；节点职责则是：

| 职责 | 用户要做的事 | 典型节点 |
|---|---|---|
| 素材输入 | 把已有内容放进流程 | 文本、图片、视频、音频 |
| AI 生成 | 根据输入创造或修改内容 | 生成图片、生成文本、生成视频 |
| 内容处理 | 对已有结果做一个明确操作 | 裁切、去背景、放大、抽帧、拼接 |
| 组织与选择 | 批量生成、比较、选择继续用哪个 | 批量、候选选择、文本拼接 |
| 查看与交付 | 检查结果、下载或导出 | 预览、结果对比、导出 |

例如“图片”是一种内容；“生成图片”“裁切图片”“查看图片”承担三个不同职责。用户之前觉得“图片”按钮含义模糊，就是这两个维度混在了一起。

**其次，一个操作是否值得独立成节点，要看用户是否需要单独控制它。**

我建议用四个问题判断：

- 用户会不会单独重跑这一步？
- 这一步的结果会不会被多个下游复用？
- 用户是否需要停下来检查、挑选或者修改结果？
- 这一步是否有独立的参数、耗时或费用？

例如“先生成四张图，再选一张做视频”，选择图片就是一个重要步骤。把它藏在自动执行里，容易导致四张图都去生成视频，费用和结果都会偏离用户意图。

比例、质量、模型选择通常可以先留在生成节点内部。等用户需要“一次比较三种模型”时，再通过分支或批量能力表达。

**第三，连线必须表达素材的用途。**

图片接入图片生成，可以是参考图片；接入视频生成，还可能是首帧、尾帧、人物参考或风格参考。FLORA 的文档已经明确区分视频输入中的首尾帧用途，Runway 则要求连接兼容的内容类型。[FLORA 连线说明](https://docs.flora.ai/editor/canvas) · [Runway 连线说明](https://help.runwayml.com/hc/en-us/articles/45763528999699-Introduction-to-Workflows)

所以我们现阶段可以先做“提示词输入”和“参考图片输入”；进入视频阶段后，再增加首帧、尾帧等角色。否则用户虽然成功连线，仍然不知道模型会如何使用这张图。

**第四，结果需要区分“跟随更新”和“固定保留”。**

这点比单独放不放输出节点更影响后续体验：

- **预览节点**跟随上游更新，适合检查当前结果。
- **保存为素材的结果**固定保留，适合选定一张图以后继续创作。
- 生成节点可以保留历史版本，让用户选择哪个版本供下游使用。

假设第一张人物图已经用于五个镜头，用户重新生成了一张人物图，下游是否立即换成新图？这应该是明确的产品行为。Runway 提供锁定节点输出的操作，FLORA 也加入固定文本和避免重复生成已完成节点的行为，说明“保留满意的结果”是实际需求。[Runway 锁定节点](https://help.runwayml.com/hc/en-us/articles/45763528999699-Introduction-to-Workflows) · [FLORA 更新](https://flora.ai/updates/more-ways-to-create-2026-09-04)

落到我们当前 Demo，我建议左上角先保留：

**文本素材、图片素材、生成文本、生成图片、预览输出。**

“参考图”可以作为图片素材连接到生成节点后的用途。“文生图”和“图生图”先由同一个生成图片节点根据输入支持，界面明确显示收到的提示词与参考图。

下一步优先通过三个真实任务打磨它：

1. 手写提示词生成图片。
2. 文本加参考图片生成新图。
3. 生成多个候选，选定一个结果，再继续修改。

观察用户在哪一步反复复制粘贴、下载再上传、担心覆盖旧结果，或者不知道该连哪里。**这些具体障碍，会比先列出几十种节点更准确地告诉我们下一种节点该做什么。**
